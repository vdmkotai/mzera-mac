# Проверка ревью и изменения Mzera 0.2.0

5 сентября 2026. Проверен документ `docs/review-2026-09-05.md`, относящийся к `99ee140`. Исправления выполнены поверх `5ff3381`, с сохранением одиночных клавиш, drag-and-drop и чёрного полноэкранного режима. Исходный документ ревью не изменён.

Основные замечания о сортировке, повторных сканах, WebP, копировании пикселей, LRU, SQLite, паузе и 10-битных кадрах подтвердились. Исправления собраны и проверены. Предложения о синхронной отрисовке, статическом FFmpeg, другом формате дискового кэша и отключении проверок эксклюзивного доступа не приняты как обязательные исправления: у них нет достаточного подтверждения выигрыша либо есть существенные ограничения.

## Измеренные результаты

Измерения выполнены на Apple M5 Pro, 64 ГБ, macOS 26.6.2, Swift 6.3.3. Это локальные прогоны, не обещание одинаковых задержек для любого файла.

| Проверка | Результат |
|---|---|
| 100 000 синтетических путей, сортировка по папкам/имени, Release | Старый компаратор 3,219 с; новые ключи 0,152 с, примерно в 21 раз быстрее |
| Сравнение двух одинаковых снимков из 100 000 записей | 29 мс |
| Вычисление видимой области, 10 000 вызовов | Среднее 0,127 мкс; не включает отрисовку |
| Обход тестовой коллекции, прогретые метаданные | ~100 тыс. файлов, 0 ошибок, 1,647 с; +2 OGV после расширения списка форматов |
| WebP 960×540, 300 кадров | Первые 20: в среднем 0,289 мс; последние 20: 0,544 мс; все кадры 123,5 мс. Измерен декодер, без загрузки в Metal |
| 10-битный HEVC, 60 кадров | Успешное декодирование, seek к началу; изображение отдельно проверено в окне |
| Подготовленные переходы в текущем GUI-прогоне | 34 показанных перехода; p50 25,94 мс, p95 26,05 мс |
| Неизменённая папка после ⌘R | Счётчик завершённых сортировок остался 3; счётчик неизменённых сканов вырос с 1 до 2 |
| FSEvents | Добавление двух тестовых файлов: 75 → 77; удаление этих копий: 77 → 75 без ручного сканирования |
| Автотесты | 36 тестов, 0 ошибок |

Источник чисел: [сохраняемые свидетельства](evidence/README.md). Имена файлов личной коллекции в JSON не включены. Обход проверяет метаданные; все 104 тысячи оригиналов не декодировались.

Цель p95 ≤16,7 мс не достигнута. Из нового короткого GUI-прогона нельзя заключить, что переключение стало быстрее прежних 24,2 мс: условия и последовательности различались. Метрика начинается в обработчике, заканчивается уведомлением Metal о показе; это не физическая клавиатура → экран. При быстрых нажатиях несколько переходов могут объединяться в один показ. `lastCPUdrawMS` включает ожидание drawable и не является чистым временем работы CPU или GPU.

## Решение по каждому пункту

«Частично» означает, что подтверждённая проблема исправлена доступным способом, но не все предложенные варианты реализованы. Неизмеренные архитектурные предложения отдельно обозначены как отложенные.

| Пункт | Проверка и решение |
|---|---|
| P0-1: дорогая сортировка | Подтверждено, исправлено. Предвычисляются натуральные ключи имён/путей и ранги папок; числовые группы сравниваются без преобразования в ограниченный размером integer. Убраны NSString-операции из горячего компаратора. Семантика стабильная и независимая от локали, поэтому может отличаться от Finder. Новый порядок помечен ключом `natural-v2`. |
| P0-2: полный повторный цикл | Подтверждено, исправлено в основных сценариях. Одинаковый снимок не вызывает сортировку, save или пересборку UI. FSEvents сверяет затронутые папки/поддеревья; пропуски событий требуют полного обхода. Готовые секции передаются с очереди сортировки. SQLite сохраняет изменения. При реальном изменении коллекция пока сортируется целиком; бинарное вставочное слияние не реализовано. Плотные номера позиций могут потребовать обновления многих строк при вставке в начало. |
| P0-3: синхронный draw как «единственный путь» | Не подтверждено. Исторические прогоны на этом Mac: событийный MTKView p95 ≈24,2 мс, прямой submit ≈28 мс, CAMetalDisplayLink ≈44 мс. Их недостаточно для универсального вывода, но они опровергают обещание автоматического улучшения. Событийная отрисовка сохранена; неработающее присваивание preferredFPS убрано. Постоянные 120 пробуждений/с для видео с меньшей частотой не введены. |
| P0-4: квадратичный WebP | Подтверждено, исправлено последовательным libwebp AnimDecoder. APNG проходит последовательный FFmpeg. Состояние композиции сохраняется, кадры не пересобираются с нуля. Полный набор кадров в RAM не хранится. Простой цикл из трёх перезаписываемых текстур не применён: два слота доставки в main queue не гарантируют завершения GPU. |
| P0-5: лишняя копия пикселей | Подтверждено, исправлено. CGContext рисует в shared MTLBuffer, texture использует тот же буфер. Выравнивание берётся у Metal device. Видеоминиатюры уменьшаются непосредственно в swscale; устранены промежуточные полноразмерные преобразования. Это не zero-copy декодирование оригинала и не обещание вдвое меньшего RSS всего процесса. |
| P0-6: работа в кадре | Подтверждено, частично оптимизировано. Структурные ключи, peek без изменения LRU, кольцо vertex buffers с ожиданием завершения GPU, сравнение значений заголовков и кэш их названий. Убрана аллокация массива из шести вершин на каждый quad. Отдельные draw calls, массив видимых индексов и небольшой массив рамки выбора остаются; «кадр совсем без аллокаций» не заявляется. |
| P0-7: вечный таймер UI | Подтверждено, исправлено. Обычный запуск обновляет статус по событиям и только при изменении значения. Таймер 1 Гц остаётся лишь при явном `--metrics`. |
| P1-1: O(n) вытеснение LRU | Подтверждено, исправлено. Словарь + двусвязный список дают O(1) touch/evict. Массовая очистка разрывает связи итеративно, без глубокой рекурсивной деинициализации. |
| P1-2: ключи и wanted | Подтверждено, исправлено. `Key: Hashable`, набор wantedKeys для проверки завершений. Обновления области объединяются в одном проходе main run loop. Это не жёсткое ограничение ровно одним обновлением на кадр. |
| P1-3: число работников | Ограничение действительно было консервативным. Миниатюры: до min(число ядер − 2, 8) задач изображений и 2 задачи видео. Экранные фото: до 2 задач, резерв срочного запроса и ограничение ожидаемого объёма текстур. Максимальный параллелизм не объявлен оптимальным для всех Mac. Аппаратное декодирование миниатюр, сокращённый probe и seek на 10% не включены: настройка декодера, readback и seek могут замедлить первое превью либо нарушить поддержку старых файлов. |
| P1-4: дисковый кэш | Транзакции, индекс, SUM и разные лимиты подтверждены и исправлены: пакет до 128 касаний или одноразовый flush через 2 с, индекс touched, учёт байтов в памяти, единый лимит. Убран отдельный fileExists перед чтением. PNG сохранён: JPEG теряет прозрачность, raw резко увеличивает объём, BC/ASTC требуют сравнения стоимости подготовки и качества. Универсальный «аппаратный JPEG за 1 мс» не подтверждён. |
| P1-5: одинаковые декоды / budget failure | Подтверждено, исправлено. После полного декода источника запись переиспользуется для больших limit. Превышение бюджета отличается от ошибки формата; доступна меньшая версия, ошибка не превращается в постоянный запрет после восстановления бюджета. Разные полезные разрешения большого оригинала по-прежнему могут сосуществовать. Тайловый просмотр не добавлен. |
| P1-6: программные видеокадры | Подтверждено, исправлено. CVPixelBufferPool и повторная настройка swscale только при изменении параметров/матрицы/range. Изменение разрешения учитывается по параметрам, а не по адресу контекста, который allocator может переиспользовать. |
| P1-7: copy-on-write пакетов | Подтверждено, исправлено. Прогрессивные массивы наполняются отдельно; отображение пакета больше не присваивает всему render.entries массив all. Финальная сортировка остаётся отдельным этапом. |
| P1-8: сканер | Set ключей вынесен из цикла, `._*` пропускаются. Остальные скрытые файлы не исключены автоматически: это могут быть нужные assets. getattrlistbulk не внедрён, обещание ускорения 3–5× для этой коллекции не проверено. Foundation-обход после изменений измерен отдельно. |
| P1-9: минификация | Принят предложенный альтернативный путь 256/512 px по фактическому размеру плитки. Mipmaps не добавлены: они увеличивают память и требуют другого пути текстур. Отсутствие любого мерцания на произвольной картинке не доказано. |
| P1-10: опрос паузы и muted PCM | Подтверждено, исправлено. NSCondition ожидает дедлайн или сигнал управления; время паузы сдвигает часы. При выключенном звуке пропускаются SWR и создание PCM-буферов. Кодек продолжает получать аудиопакеты для непрерывности. Проверка отмены permit через 20 мс остаётся только при заполненной очереди доставки. |
| P2-1: чёрный экран 10-bit | Подтверждено, исправлено. P010 video/full range через r16Unorm/rg16Unorm, правильное извлечение кодов из старших битов и отдельная матрица BT.2020 NCL. Неподдержанный pixel format даёт ошибку вместо молчания. HDR PQ/HLG, tone mapping и корректный BT.2020 gamut conversion не реализованы. Нельзя называть этот путь полноценным HDR. |
| P2-2: битый пакет останавливает всё | Подтверждено, исправлено ограниченно: AVERROR_INVALIDDATA допускает до 32 ошибок подряд, успешный кадр сбрасывает счётчик. Ошибки памяти/системы не скрываются. Это не восстановление произвольно разрушенных контейнеров; отдельная коллекция повреждённых AVI не проверялась. |
| P2-3: события во время загрузки | Подтверждено, исправлено. Запрос сверки не теряется до готовности каталога; во время скана собираются затронутые пути. Требование полного обхода сохраняется отдельно. Ошибка чтения не трактуется как достоверное удаление предыдущей коллекции. |
| P2-4: SQLite ошибки | Подтверждено, исправлено. Проверки prepare/bind/step/reset/exec, rollback всей транзакции при сбое, NULL проверяется. Тест намеренно ломает INSERT триггером и проверяет сохранность старого снимка. При повреждённой базе доступен просмотр без каталога; автоматическое восстановление базы пока отсутствует. |
| P2-5: невосстановимые бюджеты | Подтверждено, исправлено. Подписка на normal возвращает настроенные бюджеты после memory pressure. Это восстановление лимитов, а не немедленное заполнение всей RAM. |
| P2-6: зум и панорамирование | Подтверждено, исправлено. Зум удерживает точку под курсором, pan ограничивается размерами картинки. Ограничение пересчитывается и при изменении размеров окна. |
| P2-7: старые завершения | Ошибка не подтверждена самим ревью и повторной проверкой. Ключ содержит путь/метаданные; результат принимается только если он ещё нужен. Покрыто тестом замены набора желаемых запросов и игнорирования старых завершений. |
| P2-8: расширения | Добавлены jfif, jpe, jp2, heics, mpg/mpeg, 3gp, wmv, flv, ts, ogv. Распознавание расширения не гарантирует поддержку каждого профиля системным декодером. |
| P3-1: статический FFmpeg | Возможное отдельное улучшение, не доказанная причина задержки запуска. Минимальная собственная сборка не внедрена: её список кодеков/контейнеров должен покрывать фактическую коллекцию, включая APNG и добавленные форматы. Статическая линковка сама по себе не убирает ограничение deployment target. Бандл 0.2 содержит 19 библиотек, около 33,8 МиБ, включая libwebp; запуск не требует Homebrew. |
| P3-2: Package / Swift 6 / resources | Debug включает strict-concurrency=complete. Предупреждения настоящие, миграция actor/Sendable не завершена; режим языка Swift 5 сохранён. Указанные в ревью position/duration читаются и изменяются на main, локальная duration рабочего декодера — отдельная переменная. Отсутствие гонок во всём приложении этим не доказано. Пути Homebrew задокументированы, привязка сборки остаётся. Явный force unwrap URL шейдера заменён на диагностируемую ошибку; release использует metallib. Dev executable по-прежнему требует свой SPM resource bundle. |
| P3-3: сборка | Иконка кэшируется в .build с обновлением при изменении PNG/скрипта. Добавлены категория Photography, copyright, release dead_strip. Exclusivity checks не отключены. Sudden termination не включён: у приложения есть ожидающие сохранения состояния и метаданных. |
| P3-4: тесты | 36 тестов вместо 20 на момент ревью; в том числе реальные WebP/P010/software-video, rollback, pressure, переиспользование текстур, pan/zoom, FSEvents. Тайминговый тест отмены заменён на проверку доставки/отмены по событиям. Release benchmark воспроизводится отдельным скриптом; нестабильный порог по времени не превращён в функциональный unit test. Отдельный allocation trace и долгий stress test остаются непроведёнными. |
| P3-5: документация | Обновлены README и архитектура, историческая проверка помечена своей версией. Ключевые JSON сохранены в docs/evidence вместо ссылок только на игнорируемый work. |
| P3-6: мелочи | Убраны launchTime и лишние операции, заголовки скрываются при входе в viewer, выбранный путь восстанавливается через индекс, VP9 регистрируется pthread_once, ошибка запуска audio engine логируется. NSLock не заменён на атомики без замера. Переход на sRGB filtering оставлен для отдельной проверки всего цветового пути и premultiplied alpha; простая смена одного pixelFormat недостаточна. |

## Дополнительно найдено при проверке

Новая зависимость libwebp использует `@rpath/libsharpyuv.0.dylib`. Прежний упаковщик собирал только абсолютные Homebrew-зависимости и пропускал эту библиотеку. Обработаны LC_RPATH и @loader_path, добавлена проверка разрешения всех несистемных зависимостей. Готовое приложение проверено отдельно от swift build.

Повреждённый файл дисковой миниатюры теперь может быть заменён готовой копией через атомарный rename. Ранее существующий файл мешал восстановлению.

По дополнительному запросу отключена тень NSWindow в полноэкранном режиме: внешняя декорация WindowServer не должна оставлять светлый контур у borderless-окна. При выходе обычная тень восстанавливается. Полноэкранный фон остаётся #000000, переход без Spaces-анимации.

## Что проверено руками и что осталось

На безопасных тестовых изображениях проверены плоская/группированная сетка, скролл, быстрые стрелки, GIF/WebP/VP9, новый HEVC Main10, пауза WebP, F/Esc, автоматическое добавление и удаление копий через FSEvents. Оригиналы личной коллекции не изменялись. После GUI-проверки прежние настройки восстановлены; приложение открыто с сохранённой папкой и выбранным файлом. Итоговая перемещённая копия .app прошла проверку подписи и CLI-пробы HEVC Main10, WebP и APNG. На тестовом полноэкранном изображении после отключения тени светлого контура не видно.

Полная миграция на Swift 6, минимальный собственный FFmpeg, HDR, новый формат дискового кэша, многочасовой профиль памяти и задержка ≤16,7 мс остаются отдельной работой. Включённые предупреждения конкурентности нельзя считать закрытыми результатом успешной сборки. Повышенный параллелизм ограничен очередями и оценкой текстур, но строгого потолка RSS процесса нет.
