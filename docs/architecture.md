# Архитектура версии 0.2

Основной стек принят пользователем 5 сентября 2026 года. Rust + GPUI остаётся альтернативой для будущего пересмотра, если результат не устроит. Linux-репозиторий не изменён.

## Модули

| Модуль | Ответственность |
|---|---|
| AppController | Окно, команды, состояние выбора, поколения сканирования и сортировки |
| Scanner / GridLayout | Обход локального дерева и вычисление видимых плиток/секций |
| Catalog | Снимки коллекций SQLite, учёт и вытеснение дискового кэша |
| MediaCache / ImageDecoder | Ограниченные очереди, Image I/O, готовые Metal-текстуры |
| RenderView | Только видимые плитки либо текущий кадр, масштаб и положение |
| Playback | Время кадров, отмена, ограниченная доставка, звук и анимации |
| CMedia | Контейнеры FFmpeg, декодеры, VideoToolbox, конвертация аудио/программных кадров |

## Основные пути

При повторном открытии каталог читается из SQLite, затем сверяется с диском. Каталог сохраняет полный порядок записей и ключ сортировки/группировки: при совпадении ключа повторный показ не ждёт сортировки. Фильтр применяется после сортировки, поэтому сохранённый каталог всегда содержит все файлы. Первый обход выдаёт пакеты по 256 записей через канал максимум с тремя необработанными пакетами. В нём нет декодирования изображений. Натуральные ключи сортировки и ранги папок вычисляются перед сравнением; сортировка, индекс выбора и секции готовятся вне UI. Неизменённый снимок не сортируется и не сохраняется. FSEvents объединяется с задержкой: файловое событие сверяет содержащую папку, создание/удаление/перемещение папки сверяет её поддерево. Пропуск событий или ошибка чтения требует полного обхода. Изменённый снимок сортируется целиком; SQLite обновляет только изменённые строки и позиции.

Первое наполнение показывает порядок обнаружения до завершения сортировки. При смене сортировки сохраняется выбранный путь. Рекурсивный обход включает `.app`, поскольку в тестовой коллекции внутри них есть игровые изображения. Directory symlinks не обходятся, поэтому цикл ссылок не размножает записи.

Текстуры готовятся в фоновых потоках: Image I/O создаёт уменьшенное изображение с учётом ориентации, затем CGContext принудительно декодирует и приводит его к sRGB BGRA. CGContext рисует сразу в выровненный MTLBuffer; текстура использует тот же буфер, без последующего texture.replace. Выравнивание берётся у устройства. Это устраняет дополнительную копию пикселей, но не стоимость самого декодирования. Обработчик перехода использует готовую текстуру или доступную миниатюру.

Запросы объединяются по пути, размеру/дате изменения и целевому разрешению. Завершившийся старый запрос не попадает в кэш, если его больше нет в текущем наборе. Результат, не помещающийся в бюджет, отличается от ошибки декодирования; просмотрщик запрашивает меньшую версию. Полноразмерное декодированное фото переиспользуется при запросе большего limit. LRU использует словарь и двусвязный список; отрисовка читает через peek, запросы обновляют давность.

Кадр сетки зависит от числа видимых плиток. После сортировки UI получает готовые секции. Во время первого прогрессивного наполнения секции ещё пересобираются на UI-потоке в плоском режиме; массивы пополняются независимо, без общей копии на каждом пакете. При обычном просмотре изменение ширины пересчитывает геометрию по готовым секциям. Нет отдельных NSView на каждый файл. Шейдеры готовятся во время сборки приложения. Вершины используют кольцо трёх буферов, каждый освобождается для записи только после завершения команды GPU. Геометрия тайлов по-прежнему отправляется отдельными draw calls; инстансинга нет. Заголовки обновляются только при изменении значения или геометрии.

## Видео и время жизни

FFmpeg получает только локальные файлы. Для VideoToolbox регистрируется дополнительный декодер VP9. Совместимые NV12 и P010 CVPixelBuffer передаются в Metal через CVMetalTextureCache; программные кадры конвертируются в BGRA из CVPixelBufferPool. Для миниатюр swscale сразу уменьшает кадр до требуемого размера. P010 учитывает расположение 10-битных значений и limited/full range; BT.2020 NCL имеет отдельную матрицу. Это не HDR tone mapping. Pixel buffer и обёртки текстур удерживаются до завершения команды GPU.

PCM-аудио преобразуется в planar float stereo 48 kHz и поступает в AVAudioPlayerNode. При отключённом звуке сохраняется декодирование для непрерывности, но пропускаются resample и упаковка PCM. Пауза и ожидание времени кадра используют NSCondition, без постоянного опроса таймером. Видео следует отметкам времени. Накопившиеся поздние видеокадры пропускаются. Воспроизведение имеет отдельный последовательный поток; предыдущий файл отменяется перед запуском следующего.

Доставка кадров на главный поток ограничена двумя слотами. Владение слотом оформлено объектом FramePermit: даже отмена между получением слота и отправкой callback освобождает его. Это закрывает обнаруженный при ручной проверке сбой переключения анимаций.

Поле `hardwareFrames` диагностического CLI учитывает кадры в формате VideoToolbox. Для проверенных H.264 и VP9 путь FFmpeg 9 запрашивает обязательный аппаратный декодер. Не следует обобщать это на все кодеки: для некоторых, включая HEVC, FFmpeg разрешает иной режим. Основание: [FFmpeg 9.0.1, videotoolbox.c](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/libavcodec/videotoolbox.c).

## Границы версии

Последовательный WebP-декодер хранит состояние композиции вместо повторного декодирования с нулевого кадра. Холст WebP ограничен 16 мегапикселями, входной файл 512 МиБ; все кадры анимации не кэшируются. Буферы кадров остаются неизменяемыми до окончания использования GPU. APNG проходит последовательный путь FFmpeg.

Дисковые миниатюры используют PNG; выбор более быстрого формата и кэш экранных копий требуют отдельного сравнения декодеров. Звук, loop и seek реализованы, но длительная проверка синхронизации на разнообразных роликах ещё нужна. Большие RAW/HDR, управление файлами и публикация не входят в эту версию.

Проверки SQLite откатывают неуспешную транзакцию. При повреждении базы просмотр оригиналов продолжается без рабочего каталога; автоматическое восстановление базы не реализовано. Каталог и его изменяемое состояние принадлежат одной очереди. UI и кэш управляются главным потоком, декодеры работают на ограниченных очередях, управление Playback защищено NSCondition. Статическая проверка этой дисциплины в Swift 6 пока не завершена; Swift 5 language mode сохранён, Debug включает strict-concurrency=complete.
